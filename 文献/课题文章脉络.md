# 基于多智能体协作的神经退行性疾病辅助诊疗系统：文章脉络梳理

本文按已收集文献的 introduction/background 写法整理，不逐篇复述实验细节，而是抽取它们共同的叙事逻辑，帮助形成课题论文的引言、相关工作和研究意义。

## 1. 这类文章通常怎么开头

已收集文献的引言大多遵循同一个顺序：

```text
疾病负担与早诊价值
        ↓
真实诊疗依赖多源、多模态、纵向证据
        ↓
现有 AI 方法存在单模态、黑箱、缺少临床流程、缺少证据复核等不足
        ↓
LLM / Agent 带来工具调用、角色分工、知识检索和协作推理能力
        ↓
但普通多 Agent 聊天或工具堆叠仍不够，需要面向临床诊疗流程的协作机制
        ↓
提出一个多智能体辅助诊疗系统，实现证据采集、专业分析、协作复核和综合报告
```

也就是说，文章不是从“多智能体很新”开始，而是从“神经退行性疾病诊疗本身为什么复杂”开始，再推出“为什么需要多智能体协作”。

## 2. 疾病线：为什么神经退行性疾病需要辅助诊疗系统

AD、PD、PPA 等神经退行性疾病的共同特点是：病程长、早期表现隐匿、症状跨认知、行为、功能、影像和生物标志物多个层面，且不同疾病之间存在临床表现重叠。单次问诊、单一量表或单一影像模型很难覆盖真实诊疗过程。

AD 相关指南和专家共识通常先强调：

- 早期识别对延缓病程、治疗选择、照护规划和患者家庭决策具有重要意义。
- 诊断不是单一分类任务，而是病史、知情人信息、认知功能、日常功能、精神行为症状、实验室检查、MRI/PET、CSF 或血液标志物等综合判断。
- 诊疗流程需要先判断是否存在认知/功能下降，再刻画综合征，最后分析可能病因和鉴别诊断。
- 专科场景还需要根据不确定性、非典型表现、早发、快速进展等情况决定是否升级检查。

这条线可以支撑你论文中的第一层问题意识：神经退行性疾病辅助诊疗系统不能只做“AD/CN/MCI 分类”，而应服务于多源证据整合、诊断解释、风险提示、检查建议和随访管理。

## 3. 数据线：为什么单模型或单模态方法不够

多篇文章都在 introduction 中指出，现有 AI 医疗模型虽然在特定任务上表现良好，但真实场景存在以下缺口：

- **多源异构**：临床记录、量表、影像、实验室、生物标志物、遗传信息和随访数据格式不同，时间粒度也不同。
- **缺失模态**：患者不一定同时具备 MRI、PET、CSF、血液标志物或完整纵向病历。
- **纵向信息难处理**：CARE-AD 特别强调，长期 clinical notes 中包含症状演变、家属担忧、功能下降等结构化数据难以捕获的信息。
- **深度模型黑箱**：ColaCare 的引言强调，纯数据驱动 EHR 模型缺少语义知识和可解释推理，医生难以信任。
- **医学诊断不是一次性问答**：MedAgent-Pro 明确批评普通 VLM/医学 Agent 把诊断当成 one-hop VQA，缺少指南驱动的步骤、量化工具和证据检查。

这条线可以支撑你的第二层问题意识：当前系统需要从“多个模型输出结果”升级为“围绕患者证据的结构化协作与可追溯推理”。

## 4. Agent 技术线：多智能体解决的不是“人多”，而是“分工、通信和复核”

通用 Agent 文献提供的是协作机制，不是医学结论。

MetaGPT 的启发是 SOP 和结构化中间产物：复杂任务要拆成角色、流程和交接文档。迁移到诊疗系统中，可以对应病史整理、量表分析、影像分析、实验室/遗传分析、知识检索、综合诊断和报告审查。

ReConcile、TradingAgents 和多智能体辩论类工作提供“独立判断、交换理由、达成共识”的模式。医学场景不能直接照搬金融或常识推理的辩论，而应改成支持证据、反证、鉴别诊断、风险审查和不确定性保留。

GPTSwarm、G-Designer、AgentDropout 提醒我们，Agent 之间不一定永远全连接或固定流水线。协作拓扑可以随任务变化：有影像时触发影像 Agent，有纵向文本时触发文本/时间线 Agent，存在冲突时触发复核 Agent，证据不足时触发检查建议 Agent。

ArgMed-Agents、MedCollab 这类医学可解释协作工作更贴近你的课题。它们强调把讨论变成可审计的论证结构，而不是让多个 LLM 轮流聊天。适合引出你系统中“证据池、结论、反证、复核任务、最终报告”的设计。

## 5. 交叉线：神经退行性疾病 + Agent 的现有工作

这一组是你课题最直接的近邻文献，可以按功能分成四类。

### 5.1 多模态模型协调

ADAgent 重点解决 MRI/PET 等模态和不同专业模型的调度与整合。它的 introduction 先讲 AD 早诊重要性，再讲 MRI、PET、量表等多模态诊断价值，随后指出现有方法缺少面向多任务、多模态和缺失模态的协同框架。它适合用来说明：AD 辅助诊疗需要 LLM 作为工具编排器和模型结果协调器。

E2AD 虽然核心是跨模态知识蒸馏，不是典型多 Agent 诊断系统，但它说明了 AD 影像模型需要解释性报告、脑区关注和医学知识补充。它适合放在“影像模型解释与报告生成”方向。

### 5.2 纵向文本与专科会诊

CARE-AD 的文章脉络非常适合你借鉴：AD 风险长期潜伏，临床 notes 中有大量早期信号；直接让 LLM 处理原始长文本不现实，因此先做相关句抽取、症状分类、时间画像，再由多个专科 Agent 分析并由 AD 专家 Agent 汇总。它支撑的是“纵向病历文本理解 + 多专科协作评估”。

### 5.3 疾病管理型系统

AgenticAD 更像完整 AD 管理原型，覆盖照护问答、RAG 文献问答、网页抽取、表格分析、影像辅助和报告生成。它能支撑你写“辅助诊疗系统不只是预测模型，而是多功能、多阶段的临床支持平台”。但它的证据强度偏系统展示，不能当成严格临床验证。

### 5.4 其他神经退行性疾病验证

PPA 多智能体病理分类工作和 PD 多智能体临床支持工作说明，多智能体协作已经开始进入神经退行性疾病场景。PPA 文章尤其值得关注，因为它有并行专科评估、整合、专家委员会审查和反馈修订，和临床 MDT 流程非常接近。

## 6. 可以形成的综述章节结构

建议你的文献综述按下面结构写：

```text

  1.2 诊断流程：临床综合征、病因判断、分期与随访
  1.3 多源证据：量表、影像、实验室、生物标志物、遗传、文本、纵向记录

第 2 节 神经退行性疾病 AI 辅助诊断研究
  2.1 单模态影像模型
  2.2 多模态融合模型
  2.3 纵向 EHR / clinical notes 建模
  2.4 痴呆病因鉴别与混合病理识别

  5.3 对缺失模态、冲突证据和不确定性处理不足
  5.4 与临床指南、检查路径、报告生成和随访建议结合仍不充分
```

## 7. 你的论文 introduction 可以这样展开

可以按 5 段式写：

第一段写疾病背景：神经退行性疾病，尤其 AD，是老龄化背景下的重要公共卫生问题。其早期症状隐匿，诊断涉及认知、行为、功能、影像和生物标志物等多维信息，早期识别和连续管理对干预、照护规划和资源配置具有重要意义。

第二段写临床复杂性：真实诊疗并非一次性分类，而是多源异构数据的综合判断。患者可能存在数据缺失、检查时间不一致、表现非典型、合并血管性或其他神经退行性病因等情况，因此系统需要支持证据整合、鉴别诊断、不确定性表达和随访建议。

第三段写现有 AI 局限：传统机器学习和深度学习方法在影像分类、多模态融合、EHR 预测等任务中取得进展，但往往面向单一任务或固定输入，解释性不足，难以体现临床诊断流程。LLM 虽然具备医学文本理解和推理能力，但单个 LLM 容易出现幻觉、证据引用不稳定、工具选择不可靠等问题。

第四段写多智能体机会：多智能体系统能够模拟多学科诊疗协作，将病史、量表、影像、实验室/遗传、知识检索和综合报告等任务交给不同专业 Agent，并通过共享证据、冲突复核和协作整合形成更可追溯的辅助诊疗结论。

第五段写你的贡献：本文构建一个基于多智能体协作的神经退行性疾病辅助诊疗系统，面向多源异构患者数据，实现数据解析与标准化、专业 Agent 分析、医学知识检索、证据级协作复核、综合诊疗报告生成等功能，以提升系统在真实辅助诊疗场景中的可解释性、可靠性和可扩展性。

## 8. 一句话主线

本课题的主线可以概括为：

> 神经退行性疾病诊疗本质上是多源证据驱动的连续性、综合性决策任务；现有 AI 方法多停留在单模型预测或工具堆叠层面，难以支撑临床所需的证据整合、鉴别诊断和可解释复核。因此，本文引入多智能体协作机制，将不同数据来源、专业分析、医学知识和诊断复核组织为可追溯的辅助诊疗流程。

## 9. 写作时需要避免的坑

- 不要把“多模型 ensemble”直接写成“多智能体协作”。只有存在角色分工、通信、反馈、协调或任务调度时，才适合称为多智能体。
- 不要把 AD 分类任务等同于完整辅助诊疗。辅助诊疗还应包含证据解释、风险提示、鉴别诊断、检查建议和随访。
- 不要把 LLM 的自然语言解释当成严格临床可解释性。需要证据来源、时间、数据质量和模型版本支撑。
- 不要夸大 CARE-AD 的“提前十年诊断”。它更适合作为早期风险提示，且远期阳性预测能力有限。
- 不要把 MedAgent-Pro 的医学影像结果直接迁移到 AD。可借鉴其流程和证据检查思想，但 AD 的检查指标、指南和验证数据需要单独建立。
- 不要只写“多个 Agent 讨论提高准确率”。你的重点应是协作流程如何降低黑箱性、改善缺失/冲突处理、增强证据可追溯性。
