# 阶段 04 设计：专业 Agent 与确定性能力分离

## 目标

专业 Agent 只查询标准观测、调用注册工具、返回 Finding。将字段适配、数值计算、自然语言解释三个职责分开。保持程序产生的数值和日期不可被 LLM 替换，但对程序输入与计算规则也执行验证。

## 角色和能力

| 角色 | 主要能力 | 迁移来源 |
|---|---|---|
| AssessmentAgent | 条目验证、规则计分、报告分核对、维度摘要 | cognitive_agent、functional_agent |
| LongitudinalAgent | 可比性分组、时间排序、差值与描述统计 | longitudinal_agent |
| LaboratoryGeneticsAgent | 数值解析、单位/平台校验、遗传结果整理 | biomarker_agent |
| QualityService | 针对目标的数据覆盖和输入条件检查 | data_quality_agent |

代理接口：Agent.execute(TaskContext, EvidenceQuery, CapabilityInvoker) -> AgentResult。结果包括 findings、artifact_refs、requested_checks、limitations；禁止修改共享 memory。CapabilityInvoker 在执行前再次校验输入，避免规划时有效、执行时失效。

CapabilitySpec 声明输入/输出协议、适用条件、实现版本、资源、超时与可重试错误。演示能力具有独立 availability=demo，正式能力选择排除该状态。

## 量表计算

计分器只遍历 InstrumentSpec 中注册条目；备注、施测信息不进入计分。原始报告分与重算分分别作为 Observation/ToolArtifact，并创建“差异”发现；不覆盖来源分数。

支持通用加权求和、反向项目、缺项规则等已登记算子。特殊评分作为插件；例如没有完整规则时不能用简单求和替代复合评分。新量表可以只登记观测语义，尚无解释规则则输出描述结果和限制。

## 纵向分析

分组键包含主体、量表/指标版本、分数类型、必要平台和单位。比较前进行时间精度和可比性检查，再排序。两点只能支持有限描述；同日多值按明确业务策略保留或聚合，策略版本须记录。

返回 no_data、insufficient_points、insufficient_dates、not_comparable、analyzed 等明确状态。仅有效 analyzed 序列参与方向汇总；无有效序列不输出“未见明确下降”。无时间跨度不计算年化斜率。

## 检测与遗传

不能仅凭字段别名确定生物指标身份；标本、平台、单位和方法属于上下文。没有适用参考规则时呈现测量值，不套通用阈值。APOE 等稳定属性和动态检测分开处理，其时间与来源仍保存。

## 质量与事实提交

质量严重性相对于 AnalysisRequest.goal 判断。只请求量表盘点时，缺影像不应使任务失败。质量问题本身可以作为证据，但“无记录”不代表“阴性”。

计算结果先生成 ToolArtifact，再入 Evidence，最后发布 Finding。LLM 解释失败保留确定性发现；解释不得提高原结果适用范围。

## 完成定义

新专业代码不出现源字段选择逻辑；换字段名无需改 Agent；备注、缺测、乱序和混合版本能正确处理。旧算法只有在独立校验后才能复用。
