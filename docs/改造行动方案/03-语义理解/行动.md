# 阶段 03 行动：建立可靠的数据理解闭环

## 03-A1 登记领域定义

新增 registries/instruments.py、configs/instruments/xx-v1.json。先用合成定义验证接口，再逐项登记实际量表；未核实计分与版本的定义标为 candidate，不迁成 active。

每条规则必须包含来源和适用条件。不得从旧 Agent 的字符串或硬编码阈值反推它已获业务确认。

## 03-A2 实现候选 Agent 与最小网关

新增 mapping/{agent,prompts,candidate}.py 和 infrastructure/model_gateway.py。为 chat_structured 定义协议，先用 FakeModelGateway 验证错误处理，再适配 llm_client.py。

提示词输出限定已有算子、概念和版本；未知概念应返回待登记请求。非法 JSON、未知算子和超长候选返回校验失败；有限修正次数可配置，默认最多两次候选修正，是工程初始值而非效果结论。

## 03-A3 实现验证、激活与复用

新增 mapping/{semantic_validation,lifecycle,reuse}.py。把结构验证报告和语义审查报告分别持久化。生成配置化 ActivationPolicy；活跃状态不能由 Agent 自行写入。

测试“列名相同单位变化”“总分与分项歧义”“录入日期冒充测量日期”“字典版本冲突”。全量检查失败的记录不能因样本看起来正常而发布。

## 03-A4 实现补说明用例

新增 application/metadata_service.py，先提供 CLI：
查看具体问题 → 提交有出处的元数据 → 新建说明版本 → 重新验证 → 发布受影响观测修订。

这是待实现流程，不要求先做网页。一次提交附 idempotency_key，重复提交返回同一修订结果；保留旧快照。

## 03-A5 独立验证

待实现命令：
```powershell
python -m pytest tests/integration/test_semantic_mapping.py tests/integration/test_metadata_resume.py
```

先在 fake 网关上验收 S05、S06、S09，再用真实配置模型跑保留布局集，分别记录效果和成本。真实模型不可用时保留阻塞项，不把 fake 测试当自动映射效果。

产物：mapping 候选及各字段依据、验证报告、active/needs_metadata 比例、错误自动发布案例、提示词版本、补说明前后快照。

## 注意事项与回退

新建 registries/ 与 mapping 生命周期，阶段 02 人工映射仍可用。回退时禁用自动候选功能，保留已验证人工映射，不降低激活标准。

训练/示例布局与保留布局分开；测试样例不能全部来自同一字段重命名模板。无出处的评分解释即使多 Agent 同意，也不进入执行注册表。
