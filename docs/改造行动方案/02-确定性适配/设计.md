# 阶段 02 设计：可变结构的确定性适配

## 目标

把源字段解释移出专业 Agent。先用人工编写、程序验证的 MappingSpec 实现旧 JSON、CSV 长表、Excel 宽表和嵌套 JSON，验证语义协议能够承受结构变化。此时不需要 LLM。

DataQualityAgent 的 deepcopy 不能作为标准化；RWE schema2.0 只是一个来源格式。导出器继续负责取得数据，下游通过 LegacyRweAdapter 读取。

## 数据链路

InputManifest → SourceAsset → ParsedDocument → SourceProfile → MappingSpec → ValidationReport → Observation/Evidence → Snapshot。

ParsedDocument 保留原始布局及位置，不提前丢弃未知列。解析器按格式分派；schema_version 只在对应来源适配器内解释。SourceProfile 包括路径、类型、缺失、枚举样本、键候选、布局、连接基数与指纹。

## MappingSpec 结构

字段分为 source_selector、row_pipeline、identity、event、bindings、constraints、applicability、version。bindings 每条声明目标概念、源位置和值转换；转换不使用 eval 或任意 Python。

例如“每个患者 records 数组内的 result.total”应先 explode 到记录，再绑定该记录的主体、日期和总分，不能分别展开数组后按索引碰巧拼接。

算子分阶段执行：
1. select/explode/unpivot 产生保留父源位置的记录流。
2. join 使用显式键、空键策略和期望基数。
3. parse_number/parse_date/map_enum/convert_unit 对值执行声明式转换。
4. 产出语义对象及逐值 lineage。

unpivot 必须区分访视列与题目列。join 默认拒绝违反声明基数的连接，不静默生成笛卡尔积。每个算子记录输入输出条数及失败集合。

## 关联、日期和缺失

来源主体键必须带命名空间；跨来源关联通过 SubjectLink，待确认关联不参与综合。日期区分测量与录入；只有年/月时保留精度，不补造某月某日。明确 available_at 的来源；未知时不允许声称通过历史 as_of 过滤，可用取得时间作为保守可用界限并标明依据。

同日记录用原记录标识或稳定位置区分。质量问题绑定具体记录，允许合法记录部分发布；关键主体或概念不明的记录保留待补状态。

## 接口与质量报告

Parser.parse(asset) -> ParsedDocument；Profiler.profile(document) -> SourceProfile；MappingExecutor.execute(spec, document) -> CandidateBatch；MappingValidator.validate(batch, spec) -> ValidationReport。

ValidationReport 包含总记录数、已发布数、隔离数、展开计数、未映射字段、转换失败和来源定位。隔离不等于删除；用户能查看对应原值与原因。

结构指纹描述布局，语义元数据指纹描述单位/编码/版本，两者都参与后续复用。内容 hash 用于资产版本，不能当作可复用结构的唯一标识。

## 完成定义

四种结构在语义投影后与独立期望相同，所有值都可追溯；异常连接、空值、来源身份与时间边界有测试。没有任何专业 Agent 需要为了新输入字段名而修改代码。
