# 阶段 01 设计：基线、公共协议与最小存储

## 目标与边界

建立新实现的公共契约和可追溯存储，保留旧 CLI。此阶段不重写专业判断，不接入自动映射。输入先限定为有人工确认说明的合成数据和脱敏导出样例。

核查起点：main.py 直接载入 JSON；case_memory.py 保存 raw_case、normalized_case、agent_outputs、final_report；BaseAgent.run 就地修改字典。新的业务对象不能继续随 Agent 任意增删字段。

## 协议设计

建议以 Pydantic 定义边界模型，内部仓储通过 Protocol 抽象。依赖版本在实施时确认并锁定；不在文档中假定机器已有依赖。

| 对象 | 第一版必须包含 |
|---|---|
| SourceAsset | project_id、asset_id、content_hash、media_type、source_namespace、受控 URI、available_at |
| SourceLocator | asset_id/revision、record_locator、value_locator、解析器版本；页/单元格/JSON 路径为类型扩展 |
| SubjectLink | 来源主体键、统一主体引用、依据、状态 |
| Observation | id/revision、subject_ref、concept_id、类型化值、事件时间及精度、available_at、来源、验证状态 |
| Evidence | id/revision、kind、观测或工具产物引用、适用范围、依赖 |
| Finding | id/revision、具体命题、支持/反对引用、假设、限制、状态 |
| RunContext | project_id、run_id、snapshot_id、goal、as_of、配置版本；持有查询接口而非完整原始字典 |

先定义 Task、Challenge、ReportSnapshot 的最小引用结构，后续阶段扩展可选字段；用 schema_version 管理协议演进。映射有效与可解释状态分开，不设一个 success 覆盖所有环节。

## 标识与不变量

实体 ID 为不透明稳定标识，版本用 revision。唯一性约束以项目命名空间隔离。观测幂等键由来源资产版本、记录位置、概念、映射版本及派生位置构成；同数值不能去重，不同来源同一患者不能直接合并。

规则：未知主体不得统一落在名为 unknown 的共享患者下；拒绝跨主体证据组合；数值 0 不代表缺失；已发布对象不可原地修改；引用必须解析到指定版本。写入时验证不变量，读取不依赖 Agent 遵守提示词。

## 最小持久化

SQLite + 本地内容寻址资产目录。表至少为 assets、subject_links、observations、evidence、snapshots、snapshot_members、runs、schema_migrations；复杂类型存带版本 JSON，主体/概念/时间/状态另建索引。明确外键开启、事务边界与迁移编号。

快照保存成员的 id/revision，不在查询时动态选 latest。初版只实现单进程提交；任务租约和进程恢复留到阶段 08。资产先写临时文件并校验 hash，再登记；未登记文件视为待清理孤儿，不能被业务查询返回。

接口约定：
- AssetRepository.register(manifest) -> SourceAsset
- EvidenceRepository.publish(observations, evidence, idempotency_key) -> CommitResult
- SnapshotRepository.freeze(member_refs, versions) -> Snapshot
- EvidenceQuery.get(ref, project_scope) -> Evidence

## 入口与兼容

新增 multi_agent.application.cli，main.py 增加显式 --engine legacy|v2，默认 legacy。新入口只输出数据盘点和证据追溯结果，未实现分析返回 capability_unavailable。不得把空结果包装成完整分析报告。

旧输出与新输出分别存储。兼容层只能作为外层视图，新的 domain 不导入 case_memory、旧 Agent 或 DeepSeekClient。

## 完成定义

新入口无需 API Key 即可登记合成输入、重启读取观测、取得来源；重复提交不增加有效观测。旧 CLI 参数兼容。回退使用旧入口，不删除新数据库。
