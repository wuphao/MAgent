# 阶段 01 行动：建立可执行起点

前置：阅读本阶段[设计](设计.md)及[总方案](../README.md)。本阶段任务按编号顺序执行。

## 01-A1 盘点与基线

- 读取 README、main.py、case_memory.py、orchestrator.py、报告入口及依赖导入，记录 Python、GPU、DiaMond 和 LLM 的真实可用情况。
- 梳理 requirements 与 test/ 实验依赖，建立项目自己的 pyproject.toml 和锁定方案；不要直接搬运整套实验环境。
- 制作验收清单中的 XX-v1 合成样例，以及不包含患者身份的旧格式夹具。
- 在隔离输出目录运行旧流程；没有影像路径的夹具不得触发模型。分别保存无 LLM 结构化基线和缺能力结果。
- 将发现记录在 evaluation/stage-01/baseline.md；不复制 .env、数据库凭据或原始身份信息。

产物：输入清单、依赖清单、旧行为摘要、独立期望。基线无法运行时先记录具体阻塞，不把运行成功作为既成事实。

## 01-A2 建立包与协议

新增 src/multi_agent/domain/{assets,observations,evidence,runs}.py，建立项目内绝对导入和 CLI 包入口。补充 tests/unit/test_contracts.py。

先写非法值边界样例，再实现协议：未知值、模糊日期、比较符、不同主体引用、无源位置、未知版本。错误需返回稳定 code 与字段路径，避免上层解析异常中文文本。

## 01-A3 建仓储与版本

新增 storage/{sqlite,assets,snapshots}.py 及 migrations/。实现项目作用域查询、事务发布、唯一约束和快照成员表；落实数据路径从配置读取。

先发布一个观测和证据，再重复相同幂等提交、重启读取、创建新修订。检验旧快照仍解析到旧值。文件 hash 与业务键用途分开。

## 01-A4 增加新入口与对照工具

修改 main.py 做入口选择，保持原有位置参数和默认 legacy。新增 application/cli.py 的数据盘点用例，不假造最终临床报告。

新增 evaluation/compare_runs.py：只对齐确定性公共字段，将差异标为预期纠错、能力缺失、缺陷、未知；禁止简单比较整段自然语言或把输出一致当正确。

## 01-A5 出口验收

待实现命令：
```powershell
python -m pytest tests/unit/test_contracts.py tests/integration/test_storage.py
python -m multi_agent.application.cli --help
```

在可安装的项目包环境中执行。实际命令、版本与结果写入 evaluation/stage-01/acceptance.md。

通过条件：S03、协议边界和项目隔离通过；重启后可追溯；旧入口能在合成输入上运行；不调用 LLM 也能完成数据盘点。

## 修改清单与注意事项

新建 domain/、storage/、application/、tests/、pyproject.toml；少量修改 main.py。此阶段不修改全部 agents/。不要把根目录 __pycache__ 或已有输出带入包。

schema 变更必须有前向迁移；未发布开发库可重建，已验收快照不得直接清空。测试夹具不依赖作者本机绝对路径。PR 拆为“基线和契约”“仓储与新入口”两组。

回退：切回 --engine legacy；新数据库和验证材料保留用于定位问题。出口不通过则暂停源结构泛化。
