# 阶段 08 设计：恢复、增量更新、API 与默认切换

## 目标

将前七阶段的可运行闭环加固为可恢复、可部署、可持续扩展的系统。保留模块化单体；仅计算或隔离需要的能力进入工作进程。

## 事务、租约与故障恢复

任务领取使用 lease_owner、lease_expires_at、attempt_id 和单调 fencing_token。提交检查 token 与任务当前状态，旧进程租约过期后返回的结果不得覆盖新执行结果。

提交过程：
1. 工具写临时产物，生成内容指纹。
2. 登记 staging 产物并校验。
3. 资产移动到不可变最终位置。
4. 数据库事务写入有效产物、证据、任务状态及 outbox 事件。
5. 恢复器检查 staging、孤儿文件和未发送事件。

文件移动和数据库事务并非跨介质原子操作；每个中断点必须有重入处理。允许工具至少一次执行，依靠幂等键保证业务产物只有一个生效版本。外部副作用单独声明补偿/幂等条件，不能承诺天然 exactly-once。

取消请求阻止新派发；运行中任务协作取消或超时终止。晚到产物作为审计记录保留，不能自动进入已取消运行报告。

## 依赖与增量

dependency_edges 保存资产、映射、定义、观测、工具产物、发现、报告间的明确版本依赖。修订事件定位受影响闭包，去重生成新任务，并绑定新快照。

缓存采用所有相关输入、规则、工具、模型、预处理和提示词版本；未受影响分支复用原产物引用。历史报告保持原快照可读，撤回状态作为后续审计信息展示，不悄悄改写历史内容。

as_of 同时约束事件范围与当时可用数据。事后补充信息产生新的分析版本，不回填成当时已知事实。

## API 与权限

application/api.py 暴露目标架构的 datasets、profile、mappings、metadata、analysis-runs、resume/cancel、challenges、report、evidence 接口。

变更请求接受 idempotency_key；响应返回稳定标识及状态。幂等键同键不同请求体返回冲突；分页查询绑定范围和快照。错误码区分校验失败、缺元数据、能力不可用、版本冲突、超预算、技术失败。

鉴权使用项目/主体作用域，仓储层再次检查，不能只隐藏页面。未知跨项目引用与不可访问对象避免泄露存在性。上传校验大小、格式和路径范围；检索内容不能控制工具权限。

## 部署与可观测性

第一种部署：CLI/API + SQLite + 本地资产仓 + 单机工作进程。约束写入并发，使用明确事务和备份恢复流程。
第二种部署：共享数据库、对象仓与任务队列。仅在并发需求证据充分时启用，仓储协议保持不变；不能把 SQLite 文件置于共享盘冒充可靠多机数据库。

日志按 run/task/attempt/ref 关联，记录成本、队列等待、执行、失败、复核与发布。原始敏感内容走受控引用，凭据由环境/受控配置加载。

## 切换门禁

先影子运行新旧系统并分类差异；完成全部核心夹具、真实能力验证和恢复演练后将默认引擎改为 v2。旧命令在兼容窗口内显式可用，不将旧产物伪装为 v2 结果。

默认切换与旧代码删除分两步。删除条件：无运行时依赖、兼容用例通过、回退材料完整；本阶段可先保留旧模块为非默认入口。
