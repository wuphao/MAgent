# 阶段 08 行动：恢复验证、交付与默认切换

## 08-A1 加固执行持久化

新增 storage/{dependencies,outbox,leases}.py、orchestration/recovery.py。
给阶段 05 的状态库补迁移和租约字段，实现 token 校验、幂等产物提交、staging 修复和事件重复消费去重。

按四处注入故障：产物写一半、产物完成但未登记、事务提交前、事务提交后确认前。重启后检查状态和生效产物数量，不只检查程序没有抛异常。

## 08-A2 实现增量重算与历史查询

补齐 revision 事件、影响闭包和新快照创建。变更一个量表映射，检查只有相关计分、纵向、综合与报告分支更新，无关影像不重复运行。

知识规则、模型权重及提示词变更分别测试。对旧报告执行同一引用查询，应仍能返回原输入版本及后续撤回信息。

## 08-A3 实现 API

新增 application/api.py 与 requests/responses 协议，选用 FastAPI 等框架前确认项目依赖并锁定。
按 datasets → mappings/metadata → analysis-runs → 状态/质询 → 报告/证据 → resume/cancel 顺序实现。

API 调用复用 CLI 的用例服务，不能复制另一套业务流程。加入项目越权、同键不同请求体、旧版本恢复、取消并发提交及分页快照测试。

## 08-A4 部署与运维文档

新增部署配置示例，不包含真实密钥；记录 Python/GPU/模型目录、数据库与产物位置、并发和预算设置。

## 08-A6 影子运行与切换

1. 选择有明确使用范围的脱敏案例，绑定相同数据截止时间，分别运行 legacy/v2。
2. 对确定性事实、覆盖、规则适用性、限制和资源消耗做差异核查；旧输出不是金标准。
3. 修复无法解释的差异，完成真实能力验证；外部条件仍阻塞的能力明确为未交付，不能通过总验收。
4. 更新 README 与命令帮助，将默认值切至 v2，记录切换版本和数据库备份。
5. 保留 --engine legacy 的兼容入口；待无依赖后另行移除旧模块。

## 回退细节

应用回退只切入口和能力版本，不覆盖新运行数据。数据库迁移先备份并验证旧应用是否兼容新 schema；不兼容时使用对应备份的独立实例，不能让旧代码写入不认识的新库。

关闭 API 前明确在途任务去向：完成、取消或由恢复器接管。回退后不得将新报告引用指向旧 evidence 编号。

最终交付：源代码、锁定依赖、配置示例、场景夹具、实际验收报告、运行与恢复手册、能力可用清单和已知限制。文档计划完成不等于这些实施产物已经完成。
