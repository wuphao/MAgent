# 阶段 05 行动：替换固定流水线

## 05-A1 定义任务、请求和状态持久化

新增 domain/{tasks,requests}.py，storage/tasks.py。
补 runs、tasks、task_attempts、budget_ledger 表迁移，定义合法状态转换和依赖边语义。先完成状态机测试，再接并发。

## 05-A2 建模板规划器与校验器

新增 orchestration/{planner,plan_validator,goal_templates}.py。
按数据盘点、单次、纵向、多源目标逐个实现；将能力注册结果、输入覆盖和缺失条件写入计划说明。

先输出 dry-run 计划，核对任务必要性；未知工具、跨项目输入、依赖成环直接拒绝。以后增加 LLM 规划也走同一个 validator。

## 05-A3 实现执行和结果提交

新增 orchestration/{scheduler,executor,resources}.py。先串行跑同一计划，与阶段 04 对齐，再增加独立分支并发。

执行器负责前置条件复查、结果协议验证、事务发布、任务状态更新。分支失败不能吞异常后生成 succeeded；记录必要/可选依赖如何影响后续任务。

## 05-A4 完善模型网关

扩展阶段 03 的 infrastructure/model_gateway.py，迁移 BaseAgent 中各自调用 LLM 的模式。实现可配置超时、退避、结构化返回验证、token 预留与结算。

FakeModelGateway 可模拟超时、空返回、非法 JSON、未知字段和额度不足。真实供应商错误码适配独立封装，错误日志不打印请求中的敏感原文或凭据。

## 05-A5 接入 CLI

新入口支持 --plan-only 展示计划，正式执行返回 run_id、任务状态与产物引用。此阶段的报告仍可用阶段 04 的临时摘要；不能提前宣称具备反证闭环。

## 05-A6 出口验收

python -m pytest tests/integration/test_scheduler.py tests/integration/test_model_budget.py

覆盖 S13—S15，增加并发预算争抢、可选任务失败、必需任务失败和取消后不得新派发。比较串行/并发相同输入的确定性结果和引用，不要求自然语言逐字一致。

产物：目标计划样例、状态迁移记录、调用账本、串并行对照、真实模型验证说明。

## 注意事项与回退

固定 DAG 模板已能提供按需调度；不要为了动态性让 LLM 决定所有低层操作。图节点不是角色展示框，一个角色可执行多种任务，一个任务必须有清晰输入输出。

回退到阶段 04 的新协议串行驱动器，不必回退整个语义模型。调度开关只作用于新运行；在途任务先完成或明确取消，不能中途更换状态机。
