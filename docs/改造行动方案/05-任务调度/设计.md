# 阶段 05 设计：目标驱动规划、执行状态与预算

## 目标

用经过验证的任务依赖图替代 orchestrator.py 中固定 Agent 列表。第一版规划器采用显式目标模板和能力匹配，稳定后允许协调 Agent 提议计划。执行与权限仍由程序控制。

## 请求与计划

AnalysisRequest：project_id、主体范围、goal、snapshot_id、as_of、允许能力、资源和调用预算、输出要求。
TaskSpec：task_id、capability_id/version、input_refs、depends_on、required、parameters、resource_class、timeout、retry_policy、budget。

目标模板至少支持数据盘点、单次量表、纵向分析、多源综合。先查询证据覆盖，再判定能力是否适用。缺说明进入 needs_metadata，无已注册能力进入 skipped 并说明目标缺口，不创建注定不能运行的任务。

PlanValidator 检查有向无环、依赖存在、输入同项目/主体、版本一致、能力可用、参数合法和预算可容纳。校验失败不启动任何工具。

## 状态与调度

pending → ready → running → succeeded；
技术瞬时失败进入 retry_wait，有限重试后 failed；
pending 可进入 needs_metadata 或 skipped。

数据库状态转换采用预期状态条件更新。运行级 cancel_requested 防止派发新任务；任务结果提交必须检查运行是否仍可接受。阶段 08 扩展为跨进程租约与 fencing token。

依赖边声明 required_success 或 terminal：前者只接受依赖成功；后者允许读取失败/跳过作为覆盖信息。综合任务可以在可选来源失败时生成带限制结果，必需输入失败则降级或失败，不能伪装完整成功。

先实现单进程调度，支持 CPU/IO 并发池；影像进程接口先占位。并发分支输出由仓储事务合并，不允许多个 Agent 竞争同一内存字典。

## 模型网关与预算

统一 ModelGateway.chat_structured(request, output_schema, budget_context)。封装现有 DeepSeekClient，业务侧只依赖网关接口。

记录 attempt、模型/提示词版本、输入输出 token、实际费用或未知、耗时、错误。传输重试、格式修正、语义复核分别计量。费用资料未配置时不能记为零。

调用前预留额度，结束后结算；并发预留原子化，超预算不派发。token 上界和调用次数作为硬限制，费用估算作为辅助约束。响应丢失但可能已计费的调用标记 usage_unknown，不能视为未发生。

## 完成定义

无关专业任务不运行；独立分支可并发；非法计划零执行；模型超时有界退出；运行展示每个任务与预算。协调 Agent 的自由规划属于可选生成方式，不成为正确执行的前提。
