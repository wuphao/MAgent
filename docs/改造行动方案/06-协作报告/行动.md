## 06-A2 实现质询协议与反证审查

新增 domain/challenges.py、collaboration/{critic,conflict_rules}.py。首先实现报告分与计算分、时间版本、引用错误的规则审查，再接 LLM 反证。

审查输出必须通过协议验证。禁止反证 Agent 直接修改原始分数、映射或工具结果；只提交质询和动作请求。

## 06-A3 实现复核选择与闭环

新增 collaboration/{review_policy,review_router,termination}.py，接入阶段 05 任务调度。
示例流程：
1. XX 报告分为 0，但完整有效条目重算为 4。
2. 生成引用两者的冲突发现。
3. 复核计分定义、条目完整性及字段是否总分。
4. 若确认原字段是分项，发布映射修订及新观测。
5. 若确为冲突但无法回查，保留两个值，标记 unresolved；不任选一个替换。

同时实现无新增信息的重复抑制、预算耗尽和缺元数据退出。映射修订后只能重新计算受影响分析，不复用旧发现包装新报告。

## 注意与回退

“已复核”不等于“结论正确”；“多角色同意”不等于独立证据。没有新信息却持续改写措辞应立即终止。

出现循环或成本异常时关闭自动复核，仍生成专业发现和明确未审查限制。不得把未复核结果标为完成全部审查。回退报告渲染时读取原快照，不再次触发模型生成新结论。
