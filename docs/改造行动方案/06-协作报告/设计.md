# 阶段 06 设计：综合、质询、定向复核与发布

## 目标

形成第一次完整协作闭环：专业发现 → 综合候选 → 定位质疑 → 选择复核 → 新证据/限制 → 修订发现 → 统一报告。协作价值来自补充或纠正证据，不以对话轮数或 Agent 数量评价。

## 发现与综合

Finding 将数值描述、方向解释、临床含义拆成不同命题，分别列 supporting/opposing refs、scope、assumptions、limitations、status。

SynthesisAgent 查询全部相关证据索引和覆盖摘要，按需读取内容。移除 synthesis_agent.py 的证据拼接后 [:20] 截断方式；上下文预算不足时使用分块覆盖摘要，并记录未读部分，不静默丢失后续来源。

共享祖先证据用于识别相关结果，多个角色重复引用一个来源不增加独立支持强度。

## 质询协议和路由

Challenge：id、target_finding_ref、category、evidence_refs、question、requested_capability、expected_resolution、severity、status。
类型包括映射、计分、身份、时间、单位平台、影像输入、解释和缺证据。无证据引用的质疑必须明确指出缺什么及获取路径；不能只说“请重新考虑”。

先用确定性规则检测数值冲突、跨版本比较和引用问题，再由反证 Agent 审查解释与反对证据遗漏。程序校验不能证明语义蕴含，审查结果保留可核查依据和限制。

## 复核选择和终止

候选动作按硬性错误优先、结论影响、可解决性、成本排序，初版使用配置优先级，不声称已训练最优策略。

ReviewTask 绑定质询、输入快照和完成条件。复核结果为 resolved、partially_resolved、unresolved。规则冲突不意味着一定能判断原始记录哪个正确；无资料时保留未决。

重复键包含质询类别、目标命题稳定标识、证据版本集合、能力/规则版本及参数。仅换措辞不能生成新任务。初始预算示例：最多两轮复核、每轮三个新动作，并受全局调用预算约束；这些是可配置工程值，应通过评估调整。

映射修订触发新快照与受影响分支重跑。阶段 06 先对运行内显式依赖实现最小失效传播，阶段 08 补持久化恢复和跨运行增量。旧发现保留但从新发布候选中排除。

## 报告发布

ReportSnapshot 固化 run_id、snapshot_id、发现/证据版本、覆盖、未决项、状态、模型与规则版本。JSON、Markdown、TXT 仅渲染这个对象；TXT 不再独立调用模型重新推断。

发布门禁检查引用存在性、项目/主体、版本、数值单位日期、撤回状态、关键命题支持、未决限制是否继承。硬错误阻止相关命题发布；语义审查不确定时降级为带限制表述，不能自动视为通过。

整体状态 completed、completed_with_limitations、needs_metadata、failed 各有输出规范。无需资料能完成的部分可以发布，但任务缺口必须出现。

## 完成定义

至少一个冲突案例产生具体质询与定向工具调用，修订结果能追溯；另一个不可解决案例正确停止并保留限制；三种报告一致。此阶段完成 M3 核心闭环。
