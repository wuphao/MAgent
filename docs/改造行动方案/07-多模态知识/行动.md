# 阶段 07 行动：逐个补齐数据类型

## 07-A1 文本解析与观测抽取

新增 ingestion/parsers/text.py、pdf.py，agents/text.py、capabilities/text_validation.py。
先支持 txt/md 和可提取文字 PDF，再定义 OCR 能力接口。测试否定、家属病史、未来计划、时间不明、乱码和空白页。

保留完整资产、原片段和抽取版本。摘要不能成为唯一来源，页码引用不能因合并文档而偏移。

## 07-A2 建知识检索与规则候选

新增 knowledge/{documents,index,retrieval,rules}.py、agents/knowledge.py。
盘点 test/ 中 RAG 代码，只复用通过来源引用测试的独立模块；隔离旧 Web 应用和无关依赖。

导入有权使用的量表说明与数据字典；先用测试说明文档建立“问题 → 片段 → 候选定义 → 验证 → 激活”链路。旧 KnowledgeAgent 不符合新 execute 契约，重新实现而非改名接入。

## 07-A3 核查影像真实运行要求

阅读 DiaMond 调用代码、模型配置、预处理与训练输入说明，输出 evaluation/stage-07/imaging-compatibility.md。列出已确认要求、证据出处、尚未知项、GPU/权重可用性。

遇到项目外模型目录不可用，记录阻塞并完成其他能力；不能用随机数组或演示预测代替真实验收。

## 07-A4 封装影像执行

新增 capabilities/imaging/{inspect,validate,preprocess,diamond}.py。
先实现不兼容拒绝和序列选择，再在合格样本上做预处理与预测。重构缓存键和执行路径配置；并发相同输入采用幂等提交或互斥构建，禁止读取半写 H5/CSV。

输出类别、概率、类别顺序、模型适用条件、预处理与权重版本。超时关闭子进程树的策略必须在目标平台验证，避免只停止等待而 GPU 进程仍运行。

## 07-A5 接入计划与综合

为文本、知识、影像登记 CapabilitySpec 和目标模板依赖。单模态缺失不阻止其他可执行目标；模型不适用不能成为阴性发现。

让文本与量表冲突触发一次统一质询；让缺量表说明触发知识检索候选，而非绕过注册服务立即评分。
